## Decide: authored states and enhancement policy

| State       | Existing system to reuse                                  | Commerce-safe fallback                        |
| ----------- | --------------------------------------------------------- | --------------------------------------------- |
| Entrance    | Current hero/poster and collection identity               | Server-rendered title and both native actions |
| Reveal      | Editorial duration/ease and visibility-driven media       | Fully visible static image                    |
| Focus       | Micro duration, visible focus and existing control sizing | Native keyboard focus                         |
| Exploration | World chapters, collection rails and origin story         | Native anchors and direct shop link           |
| Selection   | Exact SKU card/hotspot and native variation controls      | Product name, price and canonical PDP         |
| Transition  | Existing scene handoff, normal URL/history                | Ordinary document navigation                  |
| Acquisition | Native WooCommerce cart and checkout                      | Full-page commerce forms                      |
| Exit        | Collection and all-shop actions                           | No animation or discovery gate                |

Tier 1 is the complete editorial storefront. Tier 2 adds existing authored
motion, respecting reduced motion. Tier 3 must remain optional and cannot be
accepted until lifecycle/performance tests pass. Proposed follow-up 3D budgets:
DPR 1 mobile / 1.5 desktop, no new model downloads in this batch, bounded
geometry, visibility suspension, context-loss recovery and explicit disposal.
These are acceptance targets, not claims about current implementation.

## Validation and launch gates

Before this batch, the merged runtime Node suite, product-card fixtures,
quick-view dependency fixtures and critical-rendering checks passed. An
independent reviewer found the two receipt issues above, not lost commerce
features. Mobile Home/menu/Kids were exercised in the isolated WordPress
runtime; these observations must not be represented as staging results.

Remaining gates: full route/keyboard/screen-reader matrix; missing-media and
reduced-motion browser matrix; populated cart/checkout and gateway sandbox;
mobile/tablet/desktop visual review; throttled performance and GPU tiers;
registered capability/license inventory; authenticated staging identity,
rollback archive, deployment rehearsal and founder approval. No production-ready
or launch claim is made by this first ASTRA batch.
